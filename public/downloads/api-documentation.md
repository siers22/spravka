# Приложение 3. Шаблон документации API

## Базовый URL
http://localhost:5080

## Название метода
GET /notes — получить обработанные заметки.

## Параметры
user_id — необязательный query-параметр, положительное целое число, фильтрует по ID пользователя. Если отсутствует, возвращаются все заметки. Дополнительные параметры и повторный user_id отклоняются с 400.

## Описание метода
Метод читает notes, соединяет записи с users по notes.id_user = users.id. Формирует title_user как title + " - " + login. Content сохраняется без изменений. created_at преобразуется в ДД.ММ.ГГГГ. Результат упорядочен по id.

Пример запроса:
GET http://localhost:5080/notes?user_id=2

## Формат ответа
Content-Type: application/json; массив объектов. id — число; title_user, content, formatted_date — строки.

```json
[
  {"id":1,"title_user":"Конференция ИТ - user","content":"Содержание заметки 1","formatted_date":"15.03.2027"},
  {"id":2,"title_user":"Заметка 2 - user","content":"Содержание заметки 2","formatted_date":"16.03.2027"},
  {"id":3,"title_user":"Заметка 3 - user","content":"Содержание заметки 3","formatted_date":"17.03.2027"}
]
```

## Коды ответов HTTP
| Код | Описание |
| --- | --- |
| 200 | Успех. Если нет подходящих заметок, возвращается []. |
| 400 | Неверный параметр запроса. Пример: {"error":"user_id должен быть положительным целым числом"}. |
| 500 | Ошибка подключения или чтения БД. Ответ: {"error":"Ошибка подключения к базе данных или чтения заметок"}. |

Примеры ошибок:
GET /notes?user_id=abc → 400
GET /notes?user_id=2147483647 → 200, [] (если пользователя с таким ID нет)
GET /notes при недоступной БД → 500
