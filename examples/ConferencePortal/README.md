# Конференции.РФ — учебный проект 2027

Рабочее решение образца КИМ **09.02.07-3-2027**, квалификация «Разработчик веб и мультимедийных приложений». Цель — покрыть опубликованные требования базового уровня на **75 баллов**. Окончательные баллы выставляет эксперт; закрытая детализация критериев и вариативная часть здесь не придуманы.

Стек: **PHP 8.4, ООП, PDO, MySQL 8.4, Bootstrap 5.3.8, JavaScript**. Все CSS, шрифты и изображения локальные. Composer, npm, Vue, Laravel и внешние CDN для запуска не нужны.

Регистрация, вход, личный кабинет, создание заявок, панель администратора, состояния, фильтры и отзывы реализованы через настоящую MySQL. Четыре таблицы и три внешних ключа. Администратор из КИМ: **Conf2027 / Demo77**. Минимум восемь символов применяется к регистрации обычных пользователей; административный пароль задан образцом отдельно.

## Локальный запуск на площадке (основной маршрут)

Используйте заранее установленное и разрешённое ПО. Контейнеры не требуются. Работать можно с Apache/PHP, Open Server или общим сервером площадки; адреса и путь публикации уточните у технического эксперта.

1. Проверьте `php -v` и `php -m`: PHP 8.4, PDO и pdo_mysql. Для MySQL требуется 8.0.16+; проверено на 8.4.
2. В MySQL Workbench или phpMyAdmin создайте свою БД с utf8mb4, например `conference_portal`. На общем сервере используйте выданную БД.
3. Скопируйте `config.example.php` в `config.local.php`, заполните свои параметры. Конфигурация находится вне публичной папки и исключена из Git.
4. Из корня проекта выполните `php bin/init.php`. Команда импортирует `sql/schema.sql`, добавляет три помещения и администратора. Повторный запуск не дублирует эти записи. При уже существующей иной схеме это не механизм миграций.
5. Для домашней проверки выполните `php -S 127.0.0.1:8080 -t public` и откройте [портал](http://127.0.0.1:8080/). Для Apache задайте DocumentRoot на `public`, затем используйте адрес сервера площадки. PHP нельзя открывать через `file://`.
6. Создайте своего пользователя, заявку и проверьте её администратором. Перед экзаменом разрешено проверить соединение, саму экзаменационную схему проектируют в день экзамена.

Если БД создаёт администратор сервера, ему достаточно следующего примера с собственным паролем и подходящим хостом приложения:

```sql
CREATE DATABASE conference_portal CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'conference'@'localhost' IDENTIFIED BY 'replace_with_local_password';
GRANT ALL ON conference_portal.* TO 'conference'@'localhost';
```

## Podman для разработки и проверки здесь

На машине пользователя PHP/MySQL не устанавливаются. Команды ниже запускают официальные образы. Первое получение образов требует интернета; само приложение работает без внешней сети.

```bash
cd examples/ConferencePortal
bash bin/podman.sh up
bash bin/check-podman.sh
bash bin/podman.sh down
```

Адрес: [127.0.0.1:8087](http://127.0.0.1:8087/). `PORT=8090` можно задать перед первым `up`; существующий контейнер сохраняет свой порт. Привязка только к loopback. MySQL не публикует порт. Имена ресурсов: `spravka-web-app`, `spravka-web-db`, `spravka-web-net`, `spravka-web-data`. `down` удаляет только два контейнера, том сохраняет данные. Чтобы освободить данные позже, после `down` можно явно удалить **собственный** том `podman volume rm spravka-web-data`; это необратимо для учебных записей. Чужие ресурсы скрипты не трогают.

HTTP-тесты создают отдельную БД `conference_test_*` и контейнер `spravka-web-test-*` на порту 8088 (`TEST_PORT` переопределяется). Завершение удаляет временные контейнер и БД. Основной `conference_portal` не очищается. Результат: `tests/results/http-results.json`; сохранённый запуск находится в `docs/results`.

## Принятые учебные правила

Данные проверяются сервером независимо от JS. Логин уникален без учёта регистра; регистрация требует кириллицу в ФИО, заданный телефон и корректную почту. Пароли хешируются. Владелец заявки определяется сессией; обычный пользователь не может вызвать административное действие. POST защищён CSRF. Пользовательский текст экранируется, SQL получает параметры через PDO.

Дополнительные решения, не выдаваемые за дословные требования: запрещено бронирование прошедшего времени; завершённое мероприятие не открывается повторно; отзыв один на заявку и до 2000 символов; список содержит до 12 карточек на странице. При другом реальном варианте меняйте эти решения явно вместе с проверками. Отзыв разрешается состоянием «Завершено», не просто прошедшей датой. Администратор может завершить учебное мероприятие независимо от календаря, чтобы показать сценарий на проверке. Момент начала хранится как московское время, это подписано на форме.

Документами не определены длительность мероприятия и механизм конфликтов бронирования, поэтому свободные интервалы и реальная оплата не имитируются.
