# Чудо Обувь — WPF, C#, PostgreSQL или SQL Server

Приложение для квалификации «Программист», КИМ 09.02.07-2-2027. Оконный интерфейс WPF на .NET 10; запускать на Windows.

## 1. Подготовить проект

Установите .NET 10 SDK и Visual Studio с поддержкой .NET 10, компонент «Разработка классических приложений .NET». Восстановите NuGet заранее. Распакуйте весь ZIP в `C:\Exam`: `ShoeStore` и `ShoeStore.Core` должны оставаться рядом. В Visual Studio откройте `ShoeStore/ShoeStore.csproj`.

`App.xaml` хранит Calibri и цвета компании; `.xaml.cs` создаёт подключение. `MainWindow` — каталог, `LoginWindow` — вход, `ProductWindow` — размеры модели, `CartWindow` — черновик заказа, `OrdersWindow` — список и состав заказов. Разметка — `.xaml`, события кнопок — `.xaml.cs`. Данные и операции находятся в `Data` и компилируются библиотекой `ShoeStore.Core`.

## 2. Создать БД и импортировать

Создайте пустую БД `shoe_store`. Выполните `sql/postgres-schema.sql` либо `sql/mssql-schema.sql` в этой БД. В `appsettings.json` выберите провайдер `Postgres` либо `SqlServer`, замените пароль/имя экземпляра. SQL Server может использовать Windows Authentication.

```powershell
cd C:\Exam
dotnet restore .\ShoeStore\ShoeStore.csproj
dotnet run --project .\ShoeStore\ShoeStore.csproj
```

Откроется окно каталога, без браузера и HTTP-порта. Нажмите **«Первый запуск: импорт XLSX»**. Данные читаются из `Data` рядом с `.exe`: 31 модель, 92 складские позиции, 35 размеров, 20 пользователей, 10 заказов и 30 строк. Импорт — одна транзакция, повторный импорт в заполненную БД запрещён.

Альтернатива — выполнить `sql/...-complete.sql`, который содержит сразу схему и данные. После этого импорт в приложении пропустите.

Исходные остатки уже доступны: импорт исторических заказов не списывает их повторно. Дробные размеры сохраняются как decimal. Неоднозначные названия сопоставляются явно в ImportService.

## 3. Пройти сценарий пользователя

- Гость видит каталог и подробности. Для поиска/заказа нажмите «Войти / Выйти».
- Вход **только по логину**, без пароля по условию КИМ: `isivanov` — Admin, `papetrov` — Manager, `asidorova` — User.
- ФИО и роль показаны справа сверху. Поиск проверяет название и описание; категория и порядок цены работают одновременно и обновляются без кнопки «Найти».
- Двойной щелчок по модели открывает фото, поля, весь размерный ряд и выбор только доступных размеров. Выберите целое число пар и добавьте. Количество уже в корзине учитывается при проверке.
- Корзина может содержать несколько моделей/размеров. Выберите строку, измените количество; `0` удаляет строку. Отмена очищает черновик, склад не меняется. Закрытие программы теряет только черновик.
- Подтверждение перечитывает цену и остаток в **одной транзакции**. Недостаток любой позиции отменяет весь заказ и списания. User оформляет для себя; Manager/Admin могут выбрать клиента.

Скидка **25% на модель**, если у неё нет заказов в предыдущем **календарном** месяце. Для повторяемой тренировки добавьте в корень appsettings `"CalculationDate": "2026-05-15"`: проверяется апрель 2026. **Перед сдачей удалите настройку**, чтобы использовалась текущая дата Windows.

«Много» при остатке >5, «мало» при ≤5; строка #ff8080 при ≤3. Цены decimal, итог до копеек. Изображения из `Assets/images`, отсутствующее фото заменяется `Assets/picture.png`, логотип не растягивается. Все окна имеют заголовок и иконку.

## 4. Управление заказами

Manager/Admin открывают «Заказы»: шапки с датой, ФИО и суммой; выбор шапки показывает модель, производителя, размер, количество, цену сделки и сумму строки. Для нового заказа вернитесь в каталог, соберите корзину и выберите клиента.

Manager/Admin удаляют заказ целиком, Admin дополнительно меняет дату и удаляет выбранную строку. Возврат количества и удаление происходят одной транзакцией; пустая шапка удаляется. Цены сохранённых строк не пересчитываются. После возврата из управления каталог обновляет текущую скидку и остатки.

Роль проверяется в **StoreService перед каждой операцией**, а не только при показе кнопки. User не может вызвать методы заказов; Manager не может изменить дату/удалить строку. Изменение роли в БД учитывается при следующей операции сервиса.

## 5. Собрать и сдать для Windows

```powershell
cd C:\Exam
dotnet publish .\ShoeStore\ShoeStore.csproj -c Release -r win-x64 --self-contained true -o .\publish\ShoeStore
.\publish\ShoeStore\ShoeStore.exe
```

Передавайте **всю папку**: `.exe`, библиотеки, `appsettings.json`, `Data/*.xlsx`, `Assets` с иконкой/логотипом/31 фото и заглушкой. Настройки читаются рядом с `.exe`. БД отдельно восстанавливается SQL-скриптом. Проверьте Windows-запуск из другой папки и замените подключение на сервер площадки.

ПА: база + импорт + алгоритм + каталог. ГИА: все окна и операции. В репозиторий площадки передайте файлы исходников, ER-PDF, алгоритм, SQL со **схемой и актуальными данными**, Windows-публикацию и README. ZIP на сайте служит для скачивания учебного примера, не заменяет структуру сдачи.

Скрипты `...-discount.sql` показывают параметризованный запрос C#. При ручном запуске в редакторе задайте `@previousMonthStart` и `@currentMonthStart` (SQL Server DECLARE) либо замените их на DATE-литералы (PostgreSQL).

Формы WPF требуют Windows; сборка/тесты библиотек на другой ОС не заменяют проверку поведения окон. SQL Server нужно проверить на реальном доступном экземпляре.
