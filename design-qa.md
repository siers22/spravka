# Проверка нового оформления методички

Дата: 2026-10-02. Проверка адаптации официального pixfort Documentation demo к существующему Vue-сайту.

- [Официальная главная Documentation demo](https://theme.pixfort.com/documentation/).
- [Официальный шаблон статьи Installation](https://theme.pixfort.com/documentation/installation/).
- Снимки: `docs/design/evidence/15-reference-home-viewport.jpg`, `08-reference-article.jpg`, полный экран `05-reference-documentation.jpg`.
- Само изображение указанного пользователем Dribbble-шота недоступно. Официальный live demo найден по ссылке Documentation со страницы автора. Проверка относится к этому доступному визуальному источнику; тождество историческому шоту не заявляется.

## Состояния и размеры

Desktop: 1280 × 720 CSS px, DPR 1; оба viewport-снимка 1280 × 720 px. Слева в сравнении источник, справа реализация. У источника открыты главная и Installation; у реализации — обзор и урок каталога квалификации «Программист», ГИА, светлая тема. Тексты и назначение различаются намеренно.

Снимок главной источника получен как верхние 720 px полного browser capture 1280 × 2223 px, без изменения масштаба. Более поздний снимок источника оказался 791 × 676 px после открытия панели приложения и исключён из сравнения; в evidence/15 сохранён нормализованный по кадру исходный desktop.

Mobile: 390 × 844 CSS px, DPR 1, изображения 390 × 844 px; проверены урок, меню, выбор направления и тёмная тема. Нормализация плотности не нужна.

## История исправлений

1. [P2] В первом объединённом hero дополнительная ссылка увеличивала высоту блока и сдвигала разделы. Удалена дублирующая ссылка, продолжение перенесено в быстрый переход. Новое свидетельство: `14-redesign-final.jpg` и сравнение `16-comparison-home.jpg`.
2. [P2] Первый вариант dark tokens был слишком синим относительно neutral-black live demo. Обновлены фон, текст, поверхности и границы. После исправления: `10-redesign-dark-mobile.jpg`.
3. [P2] На мобильном печать переносилась на отдельную почти пустую строку инструментов. Переставлены элементы: СУБД и печать в первой строке, стек ниже. После исправления: `10-redesign-dark-mobile.jpg`.
4. [P2] TOC не показывал текущий раздел. Добавлены синяя линия, выделение и `aria-current=location`, обновление при прокрутке. После исправления: `12-redesign-code.jpg`.
5. [P1] Проверка клавиатуры выявила отсутствие удержания фокуса в диалогах. Добавлены начальный фокус, циклический Tab/Shift+Tab и возврат после Escape. Проверены поиск и подтверждение сброса без изменения пользовательских отметок.
6. [P2] Повторное нажатие TOC с уже установленным hash не возвращало к разделу после прокрутки. Ссылки TOC направлены через существующую navigate/syncHash, которая обрабатывает тот же маршрут.

## Проверенные взаимодействия

- Выбор «Программист» и «Информационные системы» через карточки и мобильное меню.
- Программист: ПА 2 и ГИА 4 задания. Информационные системы: ПА 3 и ГИА 6 заданий.
- Поиск по выбранному курсу; поиск API вернул 9 результатов в полном маршруте информационных систем.
- Tab/Shift+Tab остаются внутри поиска и диалога сброса; Escape закрывает и возвращает фокус.
- Копирование SQL в буфер; получен фактический CREATE DATABASE / USE для SQL Server.
- Переключение PostgreSQL/SQL Server меняет код и пояснения; `aria-pressed` передаёт состояние выбора.
- Светлая/тёмная тема, открытие/закрытие мобильного меню, ссылки на разделы и активное содержание.
- Desktop и mobile390 не имеют горизонтального переполнения.
- Консоль браузера: ошибок и предупреждений нет.
- `npm run check` и `npm run build`: успешно.

## Осознанные отличия и оставшиеся ограничения

Sidebar280 вместо приблизительно333 px источника оставляет больше места длинным примерам. У hero русская вводная строка и более широкая кнопка поиска. Экзаменационные параметры заменяют клиентские логотипы. Тёмный код, интерактивные расчёты, задания и прогресс добавлены под образовательное назначение. Эти отличия приняты как адаптация продукта.

Локальный .NET ShoeStore и его белые/красные строки остаются оформлены по требованиям КИМ, включая Calibri. Клонирование их под общий дизайн нарушило бы смысл примера.

Проверка viewport320 не подтвердилась браузерным инструментом; это остаётся отдельным непроверенным размером. Печать имеет CSS-адаптацию, но фактический экспорт в PDF в этом проходе не тестировался. Исторический Dribbble-shot нельзя сопоставить пиксель в пиксель без его изображения.
