# Редактор и архив методички

Добавлено 08.10.2026. Первый выпуск — 2027. Архив предназначен для следующих студентов: после перехода к заданиям 2028 года они смогут открыть выпуск 2027 с его условиями, кодом и приложениями.

## Как это работает на GitHub

GitHub Pages обслуживает статический сайт и не запускает собственный сервер приложения. Поэтому здесь используется Git как хранилище: редактор в браузере обращается к GitHub API, записывает каталог и приложения в отдельную ветку и создаёт pull request. Владелец проверяет изменения и сливает его; существующий workflow Pages собирает обновлённый сайт.

Документация: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [Git database API](https://docs.github.com/en/rest/git), [создание pull request](https://docs.github.com/en/rest/pulls/pulls#create-a-pull-request).

Отдельные БД, сервер, платный хостинг и новые npm-пакеты не нужны. В браузере работают редактор, предпросмотр, черновики и резервные копии; для записи на GitHub нужен интернет. Ограничение экзамена «без интернета и сторонних пакетов» относится к выполнению экзаменационных заданий и не изменено этой работой.

## Открыть

После `npm run dev`:

- `http://localhost:5173/#admin` — редактор.
- `http://localhost:5173/#archive` — выпуски по годам.
- `http://localhost:5173/#year/2027/information-systems/overview` — закреплённая ссылка на ИС 2027.

На опубликованном сайте те же фрагменты добавляются к адресу сайта. Старые адреса `#information-systems/…`, `#programmer/…`, `#sql/query` продолжают работать и открывают текущий год; для ссылок на прошлые годы используйте `#year/YYYY/…`.

## Инструкция внутри редактора

Первая кнопка сверху — «Инструкция для следующего редактора». Она раскрывает порядок работы прямо на странице: доступ, подготовка нового выпуска, файлы, резервная копия, публикация и передача проекта. Инструкция доступна и без GitHub-подключения.

## Подготовить 2028 год

1. Открыть редактор, выбрать выпуск 2027.
2. Ввести 2028 в поле «Новый год», оставить «Скопировать выбранный выпуск» и нажать «Добавить год». Для пустого выпуска снять галочку.
3. Скопированные направления имеют статус **Черновик**. Это позволяет подготовить новый год, пока читателям доступен 2027.
4. Обновить номер КИМ, область, длительности, баллы, технологии, задания, код, чек-листы и файлы. Год в номере КИМ заменяется автоматически; содержание заданий необходимо проверить вручную.
5. Загрузить новые PDF/ZIP/другие приложения. Скопированные ссылки сначала ведут на прежние материалы; это удобно для сравнения, но не заменяет приложения нового года.
6. Для готовых направлений выбрать статус **Опубликован в этом выпуске**. Проверка каталога должна пройти без ошибок.
7. Нажать «Сделать текущим годом» для 2028. Выпуск 2027 останется в архиве; его редактирование по умолчанию заблокировано.
8. Создать pull request через панель GitHub. После проверки и слияния изменения появятся на публичном сайте.

Можно опубликовать следующий выпуск для просмотра в архиве заранее, не делая его текущим. Необязательно одновременно завершать все направления.

## Добавить специальность

В поле «ID нового направления» ввести свободный ID латиницей, например `network-admin`, затем «Новое направление». ID используется в URL. Можно также скопировать выбранное направление в новый ID. КИМ и название не обязаны относиться к 09.02.07.

Редактируются название, номер КИМ, описание, технологии, сроки и баллы ПА/ГИА, основной файл, статус, задания и подготовка, словарь и общие примеры кода. Для нового направления блок PostgreSQL / SQL Server выключен по умолчанию.

В задании можно добавить разделы и блоки текста, шагов, примечаний, таблиц, кода или инструкций создания БД, менять их порядок и чек-лист. «Предпросмотр» показывает выбранное задание тем же компонентом, что использует методичка. Таблицу удобно вставлять из табличного редактора: ячейки разделены табуляцией, строки — переносами.

Существующие интерактивные ER/расчёт/вход/магазин относятся к учебным данным 2027 года. Редактор позволяет вставить эти демонстрации; новый специализированный тренажёр потребует изменения Vue-компонента.

## Черновик и резервная копия

Правки и добавленные файлы автоматически сохраняются в IndexedDB браузера. Можно нажать «Сохранить черновик». При повторном открытии редактор предлагает восстановление и не заменяет черновик без выбора пользователя. Незавершённые значения, например пустой номер КИМ, можно восстановить; публикация требует устранить ошибки.

«Скачать резервную копию» создаёт JSON с каталогом, приложенными файлами и служебным SHA исходной версии. Token в неё не входит. Такая копия переносится на другой компьютер через «Импорт JSON». Редактор принимает также чистый `content/catalog.json`, если он прошёл проверку.

Браузерный черновик не синхронизируется между компьютерами. Очистка данных браузера может удалить его; резервную копию храните отдельно. Если хранилище недоступно или переполнено, редактор сообщает об этом и предлагает экспорт.

## Доступ следующему редактору

Владелец репозитория приглашает следующего студента как collaborator с правом записи. У студента собственный GitHub-аккаунт и собственный fine-grained token:

1. Выбрать владельца и только репозиторий `siers22/spravka`.
2. Repository permissions: **Contents — Read and write**, **Pull requests — Read and write**. GitHub добавляет доступ Metadata автоматически.
3. Установить подходящий срок действия и, если GitHub требует, дождаться одобрения владельца.
4. Ввести token в панели «Сохранение на GitHub» и подключиться.
5. Загрузить актуальный каталог перед началом редактирования. При подготовленных локальных правках сначала экспортировать резервную копию.
6. После отправки открыть pull request, дождаться проверок, проверить материалы и слить его в основную ветку.

Секреты в GitHub Actions добавлять не требуется. Token передаётся только фиксированному `api.github.com`, используется в памяти открытого редактора, очищается из поля после подключения и удаляется из состояния при отключении/выходе. Его нет в localStorage, IndexedDB, JSON, URL или файлах проекта.

Редактор доступен по публичному адресу без фиктивного пароля. Право записи проверяет GitHub. Это не система скрытых учебных материалов: репозиторий, каталог и даже направления со статусом «Черновик» доступны человеку, читающему исходники публичного сайта. Статус скрывает их из пользовательской навигации, а не шифрует.

При появлении новых коммитов в основной ветке отправка прекращается: экспортировать правки, загрузить актуальный каталог и перенести изменения. Если GitHub сохранил ветку, но отклонил создание PR, редактор показывает ссылку создания PR из этой ветки. Основная ветка не перезаписывается редактором напрямую.

## Файлы и хранение

| Путь | Назначение |
|---|---|
| `content/catalog.json` | Единственный источник опубликованных выпусков, направлений, уроков, словаря, кода и ссылок |
| `public/materials/2027/<course>/versions/<hash>-<name>` | Снимки первоначальных КИМ, приложений и учебных примеров |
| `public/materials/<year>/<course>/<revision>/<name>` | Новые приложения из редактора; новый файл получает новый адрес |
| `src/content/catalog.js` | Создание, копирование и проверка модели |
| `src/components/AdminPage.vue` | Редактор, черновики, загрузки, публикация |
| `src/components/BlockEditor.vue` | Поля редактирования блоков |
| `src/components/ArchivePage.vue` | Поиск и карточки выпусков |
| `src/services/github-content.js` | GitHub API, атомарный commit каталога и приложений, создание PR |
| `src/services/drafts.js` | IndexedDB; один черновик на путь сайта |
| `scripts/check-catalog.mjs` | Проверка схемы и существования файлов любого года |
| `.github/workflows/content-check.yml` | Проверки pull request до слияния |

Удаление ссылки в редакторе не удаляет файл из Git: прежний выпуск или ссылка могут продолжать на него ссылаться. История Git сохраняет предыдущие версии каталога. Восстановление опубликованных данных выполняется через revert нужного коммита/PR, после которого Pages пересоберётся.

За одну отправку: до 20 приложений, до 10 МБ каждое (в том числе Markdown и DRAWIO); каталог — до 10 МБ. Для больших исходных архивов необходимо отдельно подготовить репозиторий и ссылку, а не вставлять base64 в поля каталога. Внешние ссылки `http(s)` разрешены, локальные ссылки должны быть относительно `public/`, без начального `/` и переходов `..`.

Сайт поставляет весь каталог в сборке. При большом количестве лет стоит разделить его на лениво загружаемые выпуски; это не требуется для первых нескольких выпусков.

## Разработка и обновление C#-примеров

Данные `src/data/lessons.js`, `programmer-lessons.js`, `code.js`, `programmer-code.js` сохранены как исходные учебные материалы 2027 и используются прежними проверками. Читатель сайта теперь получает уроки и код из JSON-снимка, поэтому исправление старого JS или `examples/` само по себе не переписывает архив.

Для обновления учебного кода **текущего выпуска 2027** после изменения C#/SQL:

```sh
python3 scripts/package-examples.py
npm run content:sync-examples
npm run check
npm run build
```

Синхронизация меняет общие примеры кода и создаёт версии файлов по хешу содержимого, сохраняя старые файлы. Тексты уроков и новые направления не заменяет. Если текущим стал другой год, команда откажется автоматически менять 2027: код и файлы нового года обновляются через редактор или явную правку его JSON.

Не переписывать файлы прошлого года по прежним адресам. Если архивное задание действительно нужно исправить, отдельно разблокировать его в редакторе, приложить новый файл и оформить понятный PR с причиной исправления. Интерактивные тренажёры и browser fixtures 2027 остаются общими Vue-компонентами, их изменение нужно проверять отдельно.

## Проверки этой реализации

`npm run check` включает 16 Node-тестов: независимость годовых копий, новые направления, валидацию схемы/ссылок/кода, старые ключи прогресса, UTF-8, GitHub права, защиту от конкурирующего коммита, одну транзакцию каталога с файлами, восстановление после ошибки PR и отсутствие token в записываемых данных. Проверяет также прежние КИМ, ссылки, WPF-исходники и ZIP.

Сборка и `npm run check:pages` проверены для `/spravka/`, включая все файлы годового каталога. В Google Chrome проверены desktop 1440, mobile 390, тёмная тема, копирование 2028, новое направление, предпросмотр, загрузка PDF, экспорт, восстановление IndexedDB, блокировка архива и старый прогресс. GitHub-публикация в браузере проверена с имитацией API; реальный token не использовался, реальный PR этой проверкой не создан. Изменения подготовлены локально, публикация сайта этой работой не выполнялась.
