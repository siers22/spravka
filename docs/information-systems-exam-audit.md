# Сверка направления «Специалист по информационным системам» с КИМ и условиями экзамена

Дата: **8 октября 2026 года**. Область: `information-systems`, КИМ `09.02.07-5-2027`, приложения ПА и ГИА базового уровня, уроки сайта, ExamGuide/ExamGuide.Core/NotesApi и скачиваемые материалы. Направление «Программист» в эту сверку не входит.

**Вывод: содержание основных заданий отражено в проекте, однако текущий маршрут .NET 10 + NuGet нельзя считать подготовленным к экзамену без интернета и без установки сторонних пакетов.** В первую очередь требуется изменить способ реализации/подготовки под фактически установленное ПО. Отдельно отсутствуют готовый ER-PDF и заполненный DOCX; это недостающие примеры результата, хотя уроки объясняют необходимость их сдачи.

Сверка реализации — статическая. В этой работе не выполнялись запуск WPF, HTTP-интеграция и восстановление живых БД; новый результат runtime-проверки не заявляется.

## 2. Обязательные условия среды

### Что подтверждает КИМ

- **Страница 22:** локальная сеть без доступа в Интернет.
- **Страницы 16–18, таблица 9:** ОС, СУБД, редакторы и среда выбираются образовательной организацией. КИМ не закрепляет Windows, Visual Studio, WPF, .NET 10, PostgreSQL или SQL Server.
- **Страница 17, строка 10:** среда разработки с библиотеками предусмотрена для ГИА БУ; для ПА стоит прочерк. Следовательно, обязательный WPF/C#-импорт для выполнения ПА нельзя предполагать.
- **Страница 18:** средство тестирования API предоставляется для ГИА БУ.
- **Страница 32:** веб-сервер и возможность работы тестового клиента подготавливает технический эксперт. При необходимости регистрации используется заранее подготовленная учётная запись; личные аккаунты участников не допускаются. Допускается версия клиента без обязательной авторизации.

### Дополнительное условие пользователя

**Сторонние пакеты устанавливать нельзя.** В предоставленном КИМ не найден отдельный пункт с буквальной формулировкой этого запрета; он принят как обязательное условие данной площадки из сообщения пользователя. Нельзя подменять его предположением, что самостоятельное предварительное восстановление NuGet, перенос DLL или личного кеша пакетов разрешены.

Разрешёнными можно считать только подтверждённые компоненты уже установленной среды площадки. Обещание «заранее поставим .NET 10/Npgsql» не делает текущий пример соответствующим этому условию.

## 4. Приоритетные расхождения

### 4.1. Зависимости текущего решения не удовлетворяют принятому ограничению

[ExamGuide.Core.csproj](../examples/ExamGuide.Core/ExamGuide.Core.csproj), строки 4–7, содержит четыре внешние PackageReference:

| Пакет | Версия | Где используется |
|---|---|---|
| Npgsql | 10.0.3 | PostgreSQL-подключение в Data/Database.cs |
| Microsoft.Data.SqlClient | 6.1.7 | SQL Server-подключение в Data/Database.cs |
| Microsoft.Extensions.Configuration.Json | 10.0.0 | Настройки WPF и Database |
| Microsoft.Extensions.Identity.Core | 10.0.0 | PasswordHasher в UserRepository |

Пакеты Microsoft также объявлены как NuGet PackageReference: происхождение от Microsoft не превращает их в гарантированную часть установленной площадки. `ExamGuide` и `NotesApi` имеют ProjectReference на этот Core, поэтому отсутствие PackageReference непосредственно в их `.csproj` не означает отсутствие внешних зависимостей.

Выбор SqlServer в настройках не убирает Npgsql из сборки: оба провайдера компилируются одной библиотекой. ZIP содержит исходники, без DLL и `.nupkg`. Поэтому на компьютере с нужным SDK, но без пакетов, чистая сборка текущего примера не обеспечена.

Урок `setup/tools` предлагает «Заранее восстановите NuGet» ([lessons.js](../src/data/lessons.js), строка 62), `setup/download` содержит `dotnet restore` (строка 78). [README ExamGuide](../examples/ExamGuide/README.md) повторяет этот путь. Для данной площадки эти рекомендации должны быть заменены. `--no-restore` не создаёт отсутствующие зависимости и не решает запрет пакетов.

Self-contained publish не решает создание/сборку проекта на экзамене. Он может потребовать отсутствующие runtime packs, а сам готовый exe не отменяет требований задания и ограничений на привнесённые материалы. Допустимость переноса собственного publish здесь не подтверждена.

### 4.2. Версия и стек навязаны без подтверждения площадки

Текущие проекты target `net10.0`/`net10.0-windows`, а подготовка требует SDK 10. КИМ оставляет ПО на усмотрение образовательной организации. Нельзя считать, что .NET 10/Windows Desktop targeting pack/Visual Studio нужной версии будут установлены.

Наличие `.epf` в приложении задания 3 и упоминание 1С в инструкции техническому эксперту не делают 1С единственной обязательной платформой: основное задание допускает предоставленную СУБД/предпочтительную платформу. Но это ещё один повод не считать маршрут C# гарантированным.

Конкретный вариант без установки пакетов выбирается после подтверждения фактического ПО. Пока можно определить требования, но нельзя честно обещать сборку неизвестной средой.

Пользователь подтвердил, что состав ПО пока неизвестен и будет уточняться у преподавателя 9 октября 2026 года. До получения этого перечня решение не привязывается к новой версии .NET или другой платформе.

### 4.3. ПА излишне привязана к приложению ГИА

Общая подготовка сейчас требует открыть WPF, выполнить C#-импорт, настроить NotesApi и получить заметки. Для ПА API/авторизация не входят в задания, а IDE вообще не обязательна по инфраструктурной таблице.

Нужны два пути подготовки: ПА — офлайн-редактор ER, предоставленная СУБД, импорт JSON и SQL; ГИА — дополнительно доступная среда для приложения, HTTP-сервер и тестовый клиент. Метод импорта определить по возможностям фактической СУБД/версии, без требования скачивать инструмент.

### 4.4. Предлагаемая проверка 500 предполагает права на остановку БД

Урок `api/postman` ([lessons.js](../src/data/lessons.js), строка 1005), README и коллекция предлагают остановить службу БД через Windows Services. КИМ говорит о предоставленном сервере БД; он может быть общим. Права администратора ОС и право остановки сервера участнику не обещаны.

Тест 500 нужен, но должен затрагивать только собственное тестовое приложение/подключение. Например, для отдельного запуска своего API можно использовать заведомо недоступный адрес БД и получить реальное исключение чтения, после чего вернуть корректную конфигурацию. Конкретная процедура зависит от реализации. Нельзя останавливать общий сервер; нельзя заменять проверку БД безусловной выдачей 500. Условие валидного JSON должно проверяться и в этой ветке.

### 4.5. Не учтена подготовка тестового клиента без личной регистрации

КИМ на странице 32 прямо относит подготовку веб-сервера/учётной записи клиента к техническому эксперту. В уроках требуется Postman, но нет явной инструкции использовать предоставленный инструмент в офлайн-режиме и не регистрировать личный аккаунт.

Если на площадке другой клиент, нужно научить создавать коллекцию с тестами в нём. Не следует устанавливать Postman, его расширения, Newman или npm-пакеты на экзамене.

### 4.6. Готовые артефакты для примера результата неполны

- [er-diagram.drawio](../examples/er-diagram.drawio) содержит полную модель, но в исходниках/скачиваниях нет её готового PDF. КИМ требует именно PDF. Урок признаёт это, поэтому расхождение относится к полноте учебного примера.
- [api-documentation.md](../examples/api-documentation.md) содержит необходимые сведения, но [api-template.docx](../public/sources/api-template.docx) остаётся пустым оригиналом. Требуется заполненный документ в той же табличной структуре: верхняя строка «Базовый URL», четыре колонки метода, отдельная таблица кодов HTTP. Вставить только Markdown в отдельный документ недостаточно.
- Выход на веб-версию diagrams.net и внешнюю документацию не даёт офлайн-процедуру. Для экзамена использовать только установленный редактор. Доступность самой методички/личных материалов во время экзамена отдельно не подтверждена.

## 5. Подтверждённое совпадение функционала

### Вход и пользователи

По [AuthService.cs](../examples/ExamGuide/Data/AuthService.cs), [Puzzle.cs](../examples/ExamGuide/Data/Puzzle.cs), [UserRepository.cs](../examples/ExamGuide/Data/UserRepository.cs) и окнам:

- Логин/пароль обязательны; пустые поля не учитываются как неудачная попытка.
- Пароль проверяется по записи БД; роли называются «Администратор» и «Пользователь».
- Пазл использует четыре исходных изображения, проверяет их фактический порядок, допускает сборку обменом двух фрагментов. ТЗ разрешает произвольный метод сборки.
- Неверный пароль и/или пазл известного пользователя увеличивают счётчик один раз за отправку; третья ошибка блокирует в БД; успешный вход обнуляет счётчик.
- Есть требуемые сообщения неверного пароля, успеха и блокировки. Для неверного пазла предусмотрено отдельное пояснение.
- Администратор добавляет/меняет пользователей и снимает блокировку; дубликат логина проверяется; перед административными действиями перечитывается роль.
- Есть понятные имена элементов, комментарии к неочевидным местам и обработка исключений операций.

Наличие этих веток подтверждено чтением кода. Поведение окон, отсутствие аварий и интеграция с реальной экзаменационной БД требуют отдельного запуска на целевой среде.

### API и тесты

По [Program.cs](../examples/NotesApi/Program.cs), [NotesRepository.cs](../examples/ExamGuide/Data/NotesRepository.cs) и [коллекции](../examples/notes.postman_collection.json):

- GET `/notes` — разрешённый заданием путь; одновременное наличие `/api/notes` не требуется.
- notes имеет id/title/content/id_user/created_at и FK пользователя; C# seed добавляет 3 записи, что соответствует минимальному количеству.
- `title_user = title + " - " + login`; content без изменения; `formatted_date` — `dd.MM.yyyy`.
- В ответе нет хеша пароля/роли; это не исходный SELECT всех полей.
- Плохие query-параметры дают 400 до обращения к БД; отсутствие заметок — 200 и `[]`; исключение чтения — 500 с JSON error.
- Коллекция содержит тесты 200, 500 и валидности JSON, дополнительно 400, пустой массив, структуру и формат даты.
- `user_id` — дополнительный учебный фильтр, в ТЗ не обязателен, но допустим и описан в документации. Числовой id допустим по таблице оригинала, хотя картинка примера использует строку.

Полная проверка статусов/тестов на целевой среде остаётся необходимой после выбора реализации без запрещённых зависимостей.

## 6. Расчёт стоимости и противоречия оригиналов

Повторный расчёт использует оригинальные `Спецификация.xlsx` и `Цены.xlsx` из `БУ/Задание 1`, а количество 2 — из `Заказ покупателя.xlsx`.

| Составляющая | Расчёт на одно изделие | Стоимость |
|---|---|---|
| Столешница | 1 × 3250 | 3250,00 |
| Деталь 500×800 | 2 × 95 | 190,00 |
| Деталь 600×800 | 4 × 140 | 560,00 |
| Евровинт | 0,012 × 595 | 7,14 |
| Опора | 4 × 245 | 980,00 |
| Материалы | Сумма пяти строк | 4987,14 |
| Сборка | 0,75 × 1 × 1400 | 1050,00 |
| Распил | 1,5 × 1 × 450 | 675,00 |
| Упаковка | 0,5 × 1 × 950 | 475,00 |
| Операции | Сумма трёх строк | 2200,00 |
| Заказ, 2 изделия | (4987,14 + 2200,00) × 2 | **14 374,28** |

Ячейки норм: спецификация `J19:L21` и `L10:L14`; цены `D2:D9`; количество покупателя `S11`. Итог исходного расчётного документа `D13` — **11 448,12**, его формула `D2 = D3 + D9`, но строки используют отличающиеся суммы: материалам назначено 3948,12, операциям 7500. Это не равно расчёту по представленным нормам/ценам.

Дополнительные конфликты:

- Код стола в заказе покупателя `ФР-00000034`, в производственном заказе `НФ-00000006`; учебная модель сопоставляет по названию и сохраняет исходный код отдельно.
- Спецификация указывает винты в тыс. шт и опоры в шт; производственный документ меняет эти единицы местами при согласующихся числовых количествах.
- Цены.xlsx не содержит отдельной колонки единиц тарифа. Учебный расчёт трактует их согласованно с нормами спецификации; это допущение нужно объяснять.
- Заказ покупателя содержит продажную сумму 26 828,00; она не является искомой нормативной себестоимостью по заданию 3.

Текущие уроки эти расхождения уже объясняют. Их не следует «исправлять» подбором множителя до 11 448,12. При сдаче указать использованные источники и допущение; для нового варианта пересчитывать по его данным.

JSON-импорт также совпадает с оригиналом: шесть записей, строковые ID с нулями, ключ адреса `addres`, пустой/нетипичный ИНН сохраняется без придуманных ограничений. Дополнительный `DEMO00001` для Томилина добавлен отдельно из заказа и не считается седьмой записью JSON.

## 7. План исправления методички и примеров

1. Подтвердить перечень и версии установленной среды: ОС, IDE/runtime, СУБД/сервер, доступные библиотеки/драйверы, редактор ER, HTTP-сервер, клиент тестирования. Наличие современного SDK и библиотек нельзя предполагать.

4. Переписать шаги restore/publish/выбора версии, офлайн-редактора и клиента. Команды должны работать в новой пустой рабочей папке без личного package cache и внешней сети.
